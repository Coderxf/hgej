# 应用更新检查服务端配置

App 启动时会请求 `ApiConstants.UPDATE_CHECK_URL` 指向的 JSON 文件，若服务端 `versionCode` 大于本地 `versionCode`，弹出升级提示，点击「立即更新」用浏览器打开 `downloadUrl` 下载 APK。

## 1. 接口约定

返回一个 JSON 文件（`Content-Type: application/json`），字段如下：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| versionCode | number | 是 | 递增的整数版本号，与 `app/build.gradle` 中的 `versionCode` 比较 |
| versionName | string | 否 | 展示用版本名，如 `1.1.0` |
| downloadUrl | string | 是 | 新版 APK 下载地址（弹窗按钮直接打开该地址） |
| changelog | string | 否 | 更新说明，支持 `\n` 换行 |
| forceUpdate | bool | 否 | `true` 时弹窗不可关闭，只能点「立即更新」 |

示例见仓库 `Android_Version/server/app_update.json`。

## 2. 阿里云部署方式（二选一）

### 方式 A：ECS + Nginx 静态文件

```nginx
# /etc/nginx/conf.d/update.conf
server {
    listen 80;
    server_name your-domain.com;
    location /update/ {
        alias /data/app_update/;   # 放 app_update.json 和 apk
        autoindex off;
    }
}
```

把 `app_update.json` 和 APK 上传到 `/data/app_update/`，然后修改
`app/src/main/java/com/dt/hgej/data/api/ApiConstants.kt`：

```kotlin
const val UPDATE_CHECK_URL = "http://your-domain.com/update/app_update.json"
```

### 方式 B：阿里云 OSS（无需服务器）

1. 创建 Bucket，上传 `app_update.json` 和 APK；
2. 将文件设为「公共读」；
3. `UPDATE_CHECK_URL` 填 Bucket 的文件 URL，例如
   `https://your-bucket.oss-cn-hangzhou.aliyuncs.com/update/app_update.json`。

发新版时只需在 OSS 控制台覆盖上传新的 `app_update.json` 和 APK。

> 注意：App 已默认禁止明文 http（network_security_config）。若更新服务器暂无 https，
> 把 `app/src/main/res/xml/network_security_config.xml` 里的占位域名
> `your-aliyun-server.com` 换成你的服务器域名即可放行该域名的 http 请求；
> 建议尽快配置 https 证书，防止更新包被劫持。

## 3. 发版流程

1. 修改 `app/build.gradle`：`versionCode` 加 1（必须递增，App 以此判断是否需要升级），`versionName` 更新为展示版本；
2. 打 release 包：`./gradlew assembleRelease`（输出 `app/build/outputs/apk/release/杭工助手-v<版本>-release.apk`）；
3. APK 上传到服务器/OSS；
4. 更新 `app_update.json` 中的 `versionCode`、`versionName`、`downloadUrl`、`changelog` 并上传覆盖；
5. 老版本 App 下次启动即会收到升级提示。

## 4. App 端行为说明

- 检查在主页进入时异步执行，失败（无网络/地址未配置）静默忽略，不影响使用；
- `UPDATE_CHECK_URL` 仍是占位符（含 `your-aliyun-server.com`）时检查逻辑自动跳过；
- 「稍后再说」本次启动不再提示，下次启动仍会检查；
- `forceUpdate=true` 时弹窗无法关闭，必须更新。
